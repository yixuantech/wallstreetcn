## 0. 为什么需要这份文档

v1 的演进路径是"先做功能，再找逻辑"：MVP（晨报）→ 晚报 → 快讯 → 数据解读 → 主线 → 周报，
功能越堆越多，统一的解决问题的逻辑始终缺席——结果是每个机制单看都成立，合起来却"用起来毫无头绪"。

本文档把顺序正过来：**先推导逻辑（宪法），再用逻辑裁决一切**——包括已有功能和未来功能。

## 1. 第一性推导链

每一环从上一环必然得出，没有跳跃。

### 1.1 起点：钱包方程

把一切剥光，一个散户的盈亏只由三个变量决定：

```
收益 = f(① 持仓发生了什么, ② 市场环境怎么了, ③ 我做了什么)
```

- ①② 是世界给的，不可控——但可以"知道"
- ③ 是**唯一可控变量**

**推论 1：散户之间的差距不在①②（信息人人可得），只在③的决策质量。**

### 1.2 决策质量的三乘数

```
决策质量 = 信息完备度 × 情绪稳定度 × 纪律（错有没有被记住）
```

任何一项为零，全盘为零。三个乘数分别被三个散户结构性劣势摧毁：

| 结构性劣势 | 推导出的问题 | 后果 |
|-----------|------------|------|
| 时间稀缺（有本职工作） | **P1 怕漏事**：没时间盯，漏了就是灾难（立案公告→一字跌停） | 焦虑常驻 |
| 认知鸿沟（无财经背景） | **P2 看不懂**："PPI同比"和我的票什么关系？断了 | 被噪音驱动 |
| 情绪机器（人类出厂配置） | **P3 拿不住**：慌了就卖、热了就追 | 乱动亏钱 |
| 无记分（判断不留痕） | **P4 无成长**：十年股龄 = 一年经验重复十遍 | 原地踏步 |

**推论 2（P3 是第一性的）：散户打不赢信息战（永远比机构慢）、打不赢速度战，
唯一能赢的是"不动战"——"可以不动"是散户唯一的结构性优势（无赎回压力/无考核风险/无杠杆），
而情绪专门摧毁它。因此保护"不动的能力"是产品的最高优先级。**

## 2. 第一架构原则：注意力保护

由推论 2 直接得出：

> **无事沉默是默认状态，只有高概率重大事件才配打断用户。**

这一条解释 v1 里所有"看起来奇怪"的设计，它们不是巧合而是同一原则的实例：

| v1 已有规则 | 注意力保护的体现 |
|-----------|----------------|
| 午间无🟡以上新增 → 静默 | 没事不打扰 |
| 夜巡仅🔴关键词才推 | 睡前只有灾难才配响 |
| 🟢新增事件不推送（留给晚报） | 分诊不等于推送 |
| 盘中异动三件套、禁止裸价格播报 | 防止情绪炸弹 |
| 每日均推送 ≤ 4 条，必读仅晨晚 2 条 | 注意力预算 |

**裁决尺度：任何会提高"无事时打扰频率"的功能设计，默认违宪。**

### 2.1 表达层判例（v1.1 入宪 · 2026-08-30 Web驾驶舱+推送骨架落地后收录）

注意力保护不止管"推不推"，也管"读的人花几秒"。以下判例均已实现，作为未来表达层设计的参照系：

| 判例 | 注意力保护的体现 |
|------|----------------|
| 速览条/速览头：哨兵结论+主线+温度+胜率，4 行读完可离开 | 全貌 30 秒可读，读完即获得"离开许可" |
| 今日节奏表（晨午晚夜四班时刻） | "不实时"转为美德：一天四班，班间安心生活 |
| 透明度分级：无事个股降透明度（非折叠，信息不失联） | 注意力只给例外 |
| 颜色纪律：🔴 只属于当日警报；温度用气象色、❌灰化 | 平静是视觉常态，警报一眼可辨 |
| 变化徽标：每区标题右侧"今日有无新东西" | 看"变化"而非反复扫"存量" |
| 推送骨架差异化：必读类（晨/晚/周报）全骨架；打断类（午/夜/数据解读）仅账本尾注 | 1% 的日子，警报本身即头版，不加头版延误读取 |

## 3. 目标态：四角色

四个问题（P1-P4）的最小解，恰好是四个角色。**这就是产品的全部，不多不少。**

| 问题 | 角色 | 一句话定义 | 服务形态 |
|------|------|-----------|---------|
| P1 怕漏事 | 🛡️ **哨兵** | 替你盯盘，有事说话，无事沉默 | 分级警报 + 挂起观察点 |
| P2 看不懂 | 🗣️ **翻译官** | 把世界翻译成"你的持仓语言" | 要闻解读 + 主线地图 + 数据解读 |
| P3 拿不住 | ⚓ **锚** | 情绪发作时，用历史数据把"慌"钉住 | 情绪刻度 + 历史模式锚 |
| P4 无成长 | 🧾 **记分牌** | 每个判断记在账上，次日对答案 | 判断记分 + 周报胜率 |

### 3.1 验收标准：四感

产品是否成立，不看功能数量，看用户是否持续获得四种感受：

```
P1 → 哨兵   → 安全感："我的票没事"——30秒的确定
P2 → 翻译官 → 理解感："这事和我的票有关"——不再是旁观者
P3 → 锚     → 从容感："上次也这样，数据说不用慌"——拿得住
P4 → 记分牌 → 成长感："本周胜率67%"——看得见的变强
```

### 3.2 使用形态（目标态的日常）

```
99% 的日子 → 一条速览："哨兵：无事" → 30秒 → 回到生活
 1% 的日子 → 一条警报/🟡解读 → 3分钟 → 知道盯什么，不乱动
每周一次   → 一份周报 → 5分钟 → 看账本（胜率/主线/模式库在变厚）
```

## 4. 边界宪法

由"③ 我做了什么 = 唯一可控变量"直接推出：**系统永远不碰③。**
工具接管不可控项（信息/翻译/历史），可控项（决策）必须留给用户——否则用户永远长不出自己的判断力。

### 4.1 三不答

| 问题 | 为什么不答 | 谁的职责 |
|------|-----------|---------|
| 下一个买什么 | 荐股摧毁用户判断力，且与"受托代理人"身份冲突 | 用户 |
| 现在要不要买/卖/拿 | 方向盘永远在用户手里 | 用户 |
| 我总共赚了多少 | 账户盈亏统计是券商职责 | 券商App |

### 4.2 功能争议裁决表

（继承自《自选股功能调研报告》§0.3，作为日常争议的快速裁决索引）

| 争议场景 | 宪法裁决 | 依据 |
|---------|---------|------|
| 要不要加盘中实时推送？ | 不加（独立立项除外） | 违反注意力保护（§2） |
| AI 要不要直接给买卖建议？ | 永不 | 三不答（§4.1） |
| 这个数字让 AI 估算一下行不行？ | 不行，宁缺并标注⚪ | 事实归规则引擎（§6 对账约定） |
| 今天没事，要不要写点分析凑版面？ | 不写 | 沉默是默认值（§2） |
| 冷门股没有一致预期怎么办？ | 无锚降级，不编锚 | 诚实到刻板 |
| 数据落库替换文件存储？ | 规模/访问模式未触发条件前不迁移 | 简单实用优先 |

## 5. 现状对账章（v1 vs 目标态）

**对账结论：机制层 100% 归位，零重建；差距唯一在表达层。**

### 5.1 机制映射表

| 四角色 | v1 已有机制 | 对账结果 |
|-------|-----------|---------|
| 🛡️ 哨兵 | 分诊🔴🟡🟢⚪、三段巡检（晨/午/夜）、🔴关键词警报、观察点状态机、7天日历 | ✅ 全部就位 |
| 🗣️ 翻译官 | 说人话、逻辑链、概念卡、主线连载、数据解读三对照 | ✅ 全部就位 |
| ⚓ 锚 | 情绪刻度（0-100+历史对照）、历史模式锚归档、三件套护栏 | ✅ 就位（模式库开始积累） |
| 🧾 记分牌 | 判断记分牌、judgments流水、周报胜率、模式库 | ✅ 就位（流水待首个快照日开账） |

### 5.2 表达层差距（v1.0 指认 · 2026-08-30 已闭环 ✅）

| 差距 | 病症 | 解法 | 状态 |
|------|------|------|------|
| 推送无固定骨架 | 七栏目七种结构，每次阅读要重新定向 | 头部"四角色速览" + 尾部"账本刻度"，规则直出 | ✅ `dress_report()` 六栏目注入 |
| 四感只可见两个 | 安全感/理解感可见；从容感/成长感藏在机制深处 | 推送骨架 + Web 驾驶舱（四区+速览条） | ✅ 四感各有专属一行/一区 |
| 记忆不可见 | 用户体感"每天一份新报纸"，感知不到复利 | 账本刻度（四数字+累计）+ 变化徽标 | ✅ 每次触点可见账本变厚 |

实现形态：`three_question_digest()`（哨兵结论/主线/温度/账本，4行）+ `ledger_snapshot()`
（胜率+累计/主线/模式库/观察点 + 下一班 + 记分口径），**在 AI 输出之外拼装**——
事实与观点分离的物理保证；随报告落盘 → 推送/归档/Web 单篇页三端一致。

**原型三问对账（Web 原型验收）**：Q3 全景不焦虑——已由速览条/颜色纪律/变化徽标正面解决；
Q1 连载感 / Q2 变厚感——形态已定（主线卡片时间轴/四数字面板+流水表），待真实运行一周后用户评分。

## 6. 架构约定（由四角色派生的技术铁律）

1. **事实与观点分离**：数字、标签、✓❌、状态全部由规则引擎判定（可复算、零幻觉）；AI 只做翻译与解释，被三禁区拴住（不编数字/不给指令/不确定必须标注）。
2. **升级权单向**：AI 可将🟢升级为🟡（怕用户漏事），永不降级（防和稀泥）。
3. **降级不阻断**：任何单点损坏（接口失败/JSON漂移/数据缺失）只降级该项并如实标注，不阻断推送。
4. **有界记忆**：状态文件设截断上限（防膨胀），git 版本化（可回滚）。
5. **零值守**：cron 驱动全流程无人干预；人工干预点仅三个（watchlist/种子主线/年度假日表）。
6. **失败出声**（v1.1）：推送班次生成失败必须推送失败通知（原因 + 下一班恢复时间）——
   沉默是"无事"的专属信号，**不可被系统故障占用**。与"降级不阻断"为姊妹律：降级要标注，阻断要出声。
   （晨/晚无条件推送即天然心跳；本条覆盖"心跳停止"的故障态。）

## 7. 演进裁决原则

从此**先逻辑后功能**（反转 v1 的路径）：

```
新需求 → 过四角色（服务谁？） → 过注意力保护（会多打扰吗？） → 过三不答（越界吗？）
       → 三关全过 → 实现规划.md 立项
       → 任一关不过 → 不做，或先修订本宪法
```

**已识别的未来候选**（触发条件满足时按上述流程立项）：
- ~~表达重构（速览+账本刻度）~~ ✅ 2026-08-30 落地（见 §5.2）
- ~~Web 站点浏览历史报告~~ ✅ 2026-08-30 落地（四角色驾驶舱+归档，`site_builder.py`）
- 冷启动爬坡叙事（产品说明.md 补"第1/10/90天你会得到什么"）——服务新用户预期管理，纯文档层
- 组合层视角（第四问候选"我的持仓结构"）——触发条件：持仓 ≥ 5 只
- 数据落库（SQLite）——触发条件：模式库语义检索/盘中监控/多用户任一成立
