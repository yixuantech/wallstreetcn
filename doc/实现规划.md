> 2026-08-24 定稿｜前置文档：推送栏目总表 v2.0、部署指南-Linux

## 总览：6 个里程碑

```
M0 地基层      ▏0.5天 ▏落盘+状态+骨架 ──→ 立即上线（不影响现有晨报）
M1 晚报       ▏1.5天 ▏复盘+情绪刻度+判断记分牌
M2 午间+夜巡  ▏1.0天 ▏增量巡检+🔴警报
M3 数据解读   ▏2.5天 ▏宏观双档（侦察0.5+开发2）
M4 主线+周报  ▏2.5天 ▏认知积累闭环
M5 调度部署   ▏0.5天 ▏cron 8档 + Linux 上线
                合计 ≈ 8.5 天（协作节奏）
```

依赖链：M0 → M1 → (M2, M3 可并行) → M4 → M5。
M2/M3 互不依赖，可穿插。

## 风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| 预期值无免费源 | 中 | 降级为实际vs前值+分位（核心价值保留） |
| 情绪刻度历史锚无免费历史数据 | 高 | 自积累（每天归档，跑满1个月后启用历史对照，前期显示"积累中"） |
| AI输出的JSON块格式漂移 | 中 | 剥离失败→降级为不记分（晚报记分牌显示"今日晨报快照缺失"），不阻断推送 |
| push2直连波动 | 已知 | 腾讯备胎已上线（行情）；收盘数据接口同样配双源 |
| cron 时刻错过（服务器故障） | 低 | 晨报加补跑窗口判断（当日未推则下次运行补推） |

## 每阶段通用验收标准

1. 冒烟脚本先行（真实采集+规则计算，不调AI不推送）
2. preview 脚本生成报告落盘人工审阅
3. 真实推送1次验收
4. 连续运行3天无人工干预
