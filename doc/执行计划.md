## Phase 1：MVP核心功能

### Task 1.1：项目初始化

- [ ] 创建项目目录结构（`src/`, `tests/`, `data/`, `logs/`）
- [ ] 创建 `requirements.txt`（requests, beautifulsoup4, openai, python-dotenv）
- [ ] 创建 `.env.example`（列出所有环境变量及说明）
- [ ] 创建 `src/config.py`（环境变量读取 + 默认值）

**验收标准**：`pip install -r requirements.txt` 成功；`python -c "from src.config import Config"` 无报错

---

### Task 1.2：数据获取模块 (`src/fetcher.py`)

- [ ] 实现 `get_latest_breakfast()` — 调用信息流API获取最新早餐FM文章
  - 请求 `information-flow?channel=breakfast&limit=5`
  - 解析返回JSON，提取第一篇 `is_priced=false` 的文章
  - 返回文章ID、标题、发布时间
- [ ] 实现 `get_article_detail(article_id)` — 获取文章详情
  - 请求 `content/articles/{id}`
  - 返回完整HTML正文
- [ ] 实现 `html_to_text(html)` — HTML清洗为纯文本
  - 使用BeautifulSoup去除标签
  - 保留段落结构（用换行分隔）
  - 去除广告/推广等无关内容
- [ ] 实现 `get_market_quotes()` — 获取市场行情
  - 请求6个主要品种的实时数据
  - 格式化为可读文本（如"现货黄金 4089.26 +1.55%"）
- [ ] 统一请求封装
  - 固定Headers（Origin, Referer, User-Agent）
  - 请求间隔3秒
  - 超时设置10秒
  - 重试3次（指数退避）

**验收标准**：
- 手动运行能成功获取今日早餐FM文章全文
- 市场行情数据正确返回
- HTML清洗后文本可读、无残留标签

---

### Task 1.3：AI分析模块 (`src/analyzer.py`)

- [ ] 实现 `analyze(article_text, market_data)` — 调用DeepSeek生成报告
  - 使用OpenAI SDK（DeepSeek兼容接口）
  - System Prompt + Analysis Prompt（见design-doc.md §3.2）
  - 支持模型切换（V3/R1）
- [ ] 实现 `extract_verdict(report)` — 从报告中提取预判关键词
  - 用于推送标题（如"看偏多"）和卡片颜色
- [ ] 错误处理
  - API超时重试2次
  - 降级：返回"AI分析暂不可用"提示

**验收标准**：
- 输入早餐FM文本 → 输出结构化Markdown报告
- 报告包含四个板块（全球要闻/市场表现/逻辑分析/A股预判）
- 调用失败时有优雅降级

---

### Task 1.4：推送模块 (`src/pusher.py`)

- [ ] 实现 `FeishuPush` 类
  - POST飞书Webhook URL
  - 发送interactive卡片消息
  - 标题+Markdown内容+卡片颜色
- [ ] 卡片颜色逻辑
  - 看多→绿色，看空→红色，看平→蓝色
- [ ] 失败重试（2次，间隔5秒）

**验收标准**：
- 飞书群收到卡片消息
- 卡片颜色随预判方向变化

---

### Task 1.5：主流程编排 (`main.py`)

- [ ] 实现 `run()` 主函数
  - 串联：获取文章 → 去重 → 获取行情 → AI分析 → 推送
  - 去重：检查 `data/processed_ids.txt`
  - 记录：推送成功后写入文章ID
- [ ] 实现 `is_already_processed(article_id)` 去重检查
- [ ] 实现 `mark_processed(article_id)` 记录已处理
- [ ] 添加日志输出（print即可，后续可升级logging）

**验收标准**：
- `python main.py` 完整运行，飞书收到报告
- 重复运行不会重复推送
- 无文章时优雅退出

---

### Task 1.6：本地端到端验证

- [ ] 配置 `.env` 文件（填入真实API Key和飞书Webhook URL）
- [ ] 运行 `python main.py` 完整流程
- [ ] 检查飞书收到的报告内容质量
- [ ] 调整Prompt直到报告质量满意

**验收标准**：
- 完整流程无报错

## 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 早餐FM文章API变更 | 低 | 高 | 模块化设计，fetcher.py独立修改 |
| API需要额外认证 | 低 | 高 | 降级到网页爬取方案 |
| DeepSeek API不稳定 | 中 | 中 | 备选Qwen-Max，切换base_url即可 |
| 飞书机器人Webhook变更 | 低 | 低 | 更新Webhook URL |
| 早餐FM未按时发布 | 中 | 低 | cron触发后无文章则静默退出 |
